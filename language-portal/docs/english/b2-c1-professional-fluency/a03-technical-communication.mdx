# Technical Communication

**Level:** B2-C1 · **Goal:** explain technical systems, incidents and decisions so that both engineers and managers understand the problem, the impact and the next step.

Technical communication turns complex work into a clear explanation: **what happened, why it matters, what was done, and what comes next**. The most common failure is not grammar — it's **order**: starting with implementation details before the listener knows what the problem or the impact is.

## The pattern

> **Context → problem → impact → analysis → action → result → next step.**
>
> *Yesterday afternoon (context), the checkout service became unstable after a configuration change increased memory usage (problem). About 5% of orders failed for 20 minutes (impact). We checked logs, metrics and recent deployments and isolated the change (analysis). We rolled the configuration back (action), and error rates returned to normal (result). Next, we're adding a memory alert and a pre-release check (next step).*

### Adjust to the listener

| For engineers | For managers / non-technical listeners |
|---|---|
| Mechanism, metrics, specifics | Impact on users, time, money, risk |
| *"The pod hit its memory limit and was OOM-killed."* | *"The service ran out of memory and restarted, so some orders failed."* |
| Details on request | One analogy if it helps: *"It's like a queue at a checkout — when it gets too long, people leave."* |

Rule of thumb: **lead with impact, follow with mechanism, end with action.**

## Model sentences

- *The service became unstable after a configuration change increased memory pressure.*
- *The impact was limited to one environment, but it delayed validation for the release.*
- *We checked logs, metrics, and recent deployments to isolate the root cause.*
- *The immediate mitigation was to roll back the configuration while we prepared a safer fix.*
- *The long-term improvement is an alert and a pre-release check for the same condition.*

## Precise vocabulary

| Vague | Precise |
|---|---|
| *the system got issue* | *the service returned 500 errors / became unavailable / slowed down* |
| *we fixed it* | *we mitigated / rolled back / patched / restarted / scaled out* |
| *it was because config wrong* | *the root cause was an incorrect timeout value* |
| *some users* | *about 5% of checkout requests for 20 minutes* |
| *it will be fine* | *we expect the error rate to stay below 0.1%* |

Useful verbs: *isolate, reproduce, mitigate, roll back, roll out, deprecate, migrate, throttle, degrade, provision, validate.*

## Common mistakes

| Wrong | Right | Why |
|---|---|---|
| *System got issue and we checked logs.* | *The system had an issue, so we checked the logs and recent deployment changes.* | Precise nouns, clear sequence. |
| *Root cause was because config wrong.* | *The root cause was an incorrect configuration value.* | Avoid double-cause wording (*root cause was because*). |
| *We fixed temporary and permanent later.* | *We applied a temporary mitigation first and planned a permanent fix.* | Clear verbs and timeline. |
| *We will rollback.* | *We will roll back.* | Verb = *roll back*; noun = *a rollback*. |
| *The downtime was happened at 3.* | *The outage happened / started at 3.* | *happen* is intransitive — no passive. |
| Starting with 3 minutes of detail | Start with impact in one sentence | Listeners need the "so what" first. |
